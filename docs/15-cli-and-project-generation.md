# CLI and Project Generation

## Product role

`create-k-nex-app` and `k-nex` are a deterministic application compiler and lifecycle planner, not only a template copier.

```text
manifest + trusted manifests + exact lockfile + hermetic customer config
  → normalized desired graph
  → explicit capability/provider resolution
  → deterministic resolved graph and registries
  → Payload config, local infrastructure, migrations/tests/deployment inputs
```

## Creation flow

V1 asks for:

```text
application identity and type
preset/modules
CMS/workspace builder profiles
installed admin/public themes
Payload Postgres adapter (only supported V1 choice)
Docker Postgres or existing DATABASE_URL
object storage provider
realtime provider/topology
Dockerfile and local Git initialization
```

A driver selection proposes `module.logistics.core` and a provider for `realtime.gateway`; it never silently installs them in non-interactive mode.

```bash

k-nex enable <plugin-id>
k-nex remove <plugin-id> --mode purge

k-nex doctor --ci
k-nex inspect
k-nex upgrade
k-nex db generate|migrate|status
k-nex manifest migrate
k-nex theme add|remove|set|validate
```

Schema-owning V1 plugins do not expose a generic retained-data uninstall command. CLI can plan disable/re-enable, explicit archive/export project, or explicit purge migration.

## Determinism

Inputs include exact CLI/resolver/schema versions and package integrity. Outputs are canonical and timestamp-free. Filesystem traversal order, locale, hostname, absolute path, current time, random values, and secret values cannot affect generated bytes.

CI:

```text
clean checkout A → generate
clean checkout B → generate
compare deterministic artifacts byte-for-byte
compare with committed artifacts
```

## Planner and apply

Every material command produces a plan covering:

```text
manifest/package/lock changes
provider selection and process topology
Payload schema/migration impact
source/action/block/theme/reference impact
environment names and infrastructure
lifecycle and rollback limitations
```

The plan includes source state and expires if manifest/lock/config fingerprint changes. Apply writes to staging, validates, then atomically replaces files where possible. No add/remove/generate command runs a production migration.

## Resolver behavior

- exact application package versions;
- explicit provider when a single capability has multiple candidates;
- optional package activates only if explicitly installed;
- prerelease excluded unless exactly requested;
- conflicts and shortest dependency cycles fail;
- resolver semantics versioned and golden-tested;
- canonical `k-nex.resolved.json` committed.

## Registry generation

The generator writes static imports for packages already present in the lockfile. Runtime database values cannot name imports.

Expected and actual contribution inventories are compared at boot. A plugin requesting an undeclared capability or registering an undeclared ID fails.

## `k-nex.config.ts`

Executed in a constrained generation context:

```text
network denied
clock/random not exposed for registration IDs
process.env cannot choose graph branches
imports limited to source-controlled declared packages
writes limited to staged output
transitive source fingerprint recorded
```

Customer handler runtime may read validated environment values after composition has frozen.

## `doctor`

Checks include:

```text
manifest/schema/ID grammar
package/lock/manifest integrity
Payload/Node/pnpm compatibility
provider cardinality and topology
actual versus declared contributions
server/browser dependency boundaries
stale deterministic output
migration predecessor/readiness
schema-owning lifecycle restrictions
orphan block/source/action/field references
gateway budgets/cache classifications
realtime convergence settings
active theme/layout compatibility
```

An in-memory realtime adapter with separate worker publication paths is an error.

## Secret and process safety

- masked secrets only in ignored local or deployment secret stores;
- process execution uses argument arrays, never shell interpolation;
- template paths remain inside repository root;
- install scripts are denied or explicitly reviewed;
- private scope registry is pinned;
- logs redact database/Redis/provider credentials.

## Testing

- interactive/non-interactive parity;
- resolver golden corpus;
- secret/path/shell injection;
- filesystem rollback;
- byte-identical generation;
- packed-package exports/types;
- clean and previous-release Postgres migration fixtures;
- deliberate legacy ID/manifest/registration failures;
- supported operating system path/process behavior.
