# External References

K-Nex architecture remains product-specific. External projects are implementation candidates, adapters, protocols, or supporting tools—not the source of K-Nex product boundaries.

Primary documentation must be rechecked when implementation begins and whenever a dependency/protocol is upgraded because APIs, licenses, support matrices, security guidance, and hosting behavior can change.

Reference catalogs:

1. [General platform, Payload, builder, operations, security, and package references](./references-general.md)
2. [Agent tool and Model Context Protocol references](./references-agent-tools.md)

Implementation reports record the exact versions/specification revisions actually tested. A third-party feature list never establishes a K-Nex security, migration, lifecycle, authorization, or durability guarantee.
